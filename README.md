# wwan-manager: LTE connection

Debian package that brings up a Sierra Wireless **EM7455** / Dell
**DW5811e** LTE modem as an ifupdown interface (default `wwan0`), **dialed on
demand**: `ifup wwan0` dials, `ifdown wwan0` hangs up. Nothing dials by
itself. It doesn't depend on any user of the connection.

Supported: the EM7455 (M.2 in a USB adapter), `1199:9071`, and the DW5811e,
either with Dell's identity `413c:81b6` or converted to the Sierra one, both
in QMI configuration. Tested: an EM7455 (firmware SWI9X30C_02.39.00.00) and
a DW5811e (EM7455B, now on the same firmware) converted to the Sierra
identity.

## How it works

The interface is `inet manual`: `ifup`/`ifdown` run `wwan-dial up`/`down`.
The data session is a QMI WDS session; the firmware only does raw IP, so
there is no DHCP and the address comes from the modem.

- `wwan-dial up`: waits for the QMI and AT ports, switches `qmi_wwan` and
  the modem to raw IP, sends the FCC unlock and sets the modem online,
  waits for network registration (up to 120 s), starts the session (3
  attempts), sets address, gateway, MTU and DNS from QMI "WDS Get Current
  Settings", and puts the routes into their own table (see
  [Routing](#routing)). A failed dial undoes everything, as `ifdown` would.
- `wwan-dial down`: removes address, routes and rules, then ends the
  session. It also works while `wwan0` is down.
- `wwan-dial off`: `down`, then switches the modem to low-power mode: the
  radio is off and the modem leaves the network (its LED goes off). With
  `LOW_POWER=yes`, `down` (and so `ifdown`) does the same; otherwise it
  leaves the radio on and the modem registered. The next `wwan-dial up`
  (`ifup wwan0`) sets it online again.
- `wwan-dial on`: sets the modem online again (raw IP, FCC unlock, online
  mode, as `up` does before dialing) without dialing.

| Installed file | Purpose |
|---|---|
| `/usr/sbin/wwan-dial up [--profile N]\|down\|off\|on` | Dials (profile N instead of `QMI_PROFILE`), hangs up, hangs up and switches the radio off, or switches it on, as above; logs to the journal |
| `/usr/lib/wwan-manager/qmi` | Minimal QMI client: one request to a QMI service via `/dev/cdc-wdmN`, response as TLVs; can keep its client id for WDS sessions |
| `/usr/sbin/wwan-at` | Sends AT commands to `AT_PORT`, serialised with flock |
| `/usr/sbin/wwan-sim [--force] [1\|2\|2 off]` | Shows or switches the active SIM (dual-SIM carrier boards) or disables slot 2, see [Dual SIM](#dual-sim) |
| `/usr/sbin/wwan-pin [off\|change]` | Shows the SIM PIN state, switches the PIN lock off or changes the PIN, see [SIM PIN](#sim-pin) |
| `/usr/sbin/wwan-apn [--force] [--profile N] [APN [TYPE]]` | Shows or sets the APN, see [APN](#apn) |
| `/usr/sbin/wwan-manager-setup` | Generates the ifupdown stanza and the interface-name udev rule from the settings; renames an already present modem interface |
| `/usr/share/bash-completion/completions/wwan-{dial,sim,pin,apn}` | Bash completion of the subcommands, `--force` and the PDP type (needs the `bash-completion` package) |
| `/usr/lib/udev/rules.d/90-wwan-manager.rules` | `/dev/wwan-at` symlink to the AT port on USB interface 03 (`1199:9071`, `413c:81b6`) |
| `/etc/network/interfaces.d/wwan-manager` | *Generated:* `iface <LTE_IFACE> inet manual` with `up`/`down` `wwan-dial`; no `auto`/`allow-hotplug` |
| `/etc/udev/rules.d/90-wwan-manager-ifname.rules` | *Generated:* names the modem's network interface `LTE_IFACE` |
| `/etc/default/wwan-manager` | Settings |

**Nameservers:** `/etc/resolv.conf` is never touched. `/run/wwan/<iface>.dns`
holds `DNS` (default `1.1.1.1`) or, with `DNS` empty, the modem's servers,
for whoever routes traffic over LTE.

### Modem quirks handled

- **Raw IP only.** The firmware refuses Ethernet framing (WDA data format
  stays `raw-ip`), so there is no DHCP. `wwan-dial` switches `qmi_wwan` to
  raw IP and sets address, gateway, MTU and DNS from QMI.
- **The session belongs to a QMI client.** The WDS session ends when its
  client id is released. `wwan-dial` keeps the client id and session handle
  in `/run/wwan/<iface>.qmi` until hang-up.
- **Not ready right after power-up.** `wwan-dial` waits for network
  registration and retries the dial up to 3 times. `wwan-at` sends `ATE0`
  first, because echo returns after every power-up.
- **Unstable names.** The rule generated by `wwan-manager-setup` names the
  network interface `LTE_IFACE`; `/dev/wwan-at` doesn't depend on `ttyUSB`
  numbering.
- **Never open a missing serial port.** That would create a regular file
  blocking the real device node. `wwan-at` refuses to run unless the port is
  a character device.
- **IPv4 only.** The EM7455 supports IPv4+IPv6, but `wwan-dial` starts an
  IPv4 session.

### Routing

The LTE routes live in their own routing table, `TABLE` (default 700), so
bringing LTE up does not take traffic away by itself: the main table never
gets an LTE default route. After the address is set, `wwan-dial`

- moves the interface's gateway routes (the default route, metric
  `METRIC`) from the main table into `TABLE`;
- copies its subnet route into `TABLE`. It stays in the main table too, so
  routes added there via the LTE gateway (such as a VPN server route) still
  work;
- adds three rules with priority `RULE_PREF` (default 1000):
  `oif <LTE_IFACE> lookup TABLE`, for traffic bound to the interface
  (`curl --interface`, `ping -I`, `SO_BINDTODEVICE`),
  `from <LTE address> lookup TABLE`, for traffic sent from its address, and
  `fwmark FWMARK lookup TABLE` (default 700), for marked traffic (`SO_MARK`).

Hang-up removes the rules and empties the table. With `TABLE` empty,
everything stays in the main table, with the default route behind the
primary's by its metric.

```sh
ip route show table 700
ip rule
ip route get 1.1.1.1 oif wwan0   # → via the LTE gateway, table 700
```

## Modem setup

The module must be in the QMI USB configuration, `AT!USBCOMP=1,1,0000010D`
(diag, nmea, modem, rmnet0), followed by `AT!RESET`; both the EM7455 and the
DW5811e come in MBIM configuration. Extended commands are unlocked with
`AT!ENTERCND="A710"`. A DW5811e can keep Dell's identity (`413c:81b6`) or be
converted to the Sierra one (`1199:9071`). Step by step, including the
conversion, the FCC lock and the firmware update:
[EM7455-SETUP.md](EM7455-SETUP.md).

## FCC lock

Laptop modules keep the radio off until the host sends the "FCC
authentication" (`BIOS` vote in `AT!PCINFO?`). `wwan-dial` sends the
per-session unlock (QMI DMS `0x555F`) before every dial, so modules with the
lock enabled work; on unlocked modules it has no effect.

## Dual SIM

The module has two SIM interfaces (`AT!UIMS: (0-1)`). On a dual-SIM carrier
board that wires its second slot to the module's UIM2 pins, they are slot 1
and slot 2; `wwan-sim` switches between them. Boards that instead select
the slot with a switch or jumper need no software switch.

```sh
wwan-sim            # active slot, UIM2 state, SIM, operator, registration, APN
wwan-sim 2          # use slot 2
wwan-sim 1          # back to slot 1
wwan-sim --force 2  # also while LTE is up
wwan-sim 2 off      # disable slot 2 again (UIM2), back to slot 1
```

Switching:
1. refuses while LTE is up (`ifquery --state wwan0`) unless `--force`;
2. hangs up LTE;
3. the first time slot 2 is chosen: enables the second interface
   (`AT!CUSTOM="UIM2ENABLE",1`, off by default) and resets the modem;
4. selects the slot (`AT!UIMS=0|1`, after `AT!ENTERCND="A710"`);
5. waits for the SIM (30 s), switches the radio on if it is off (after
   `wwan-dial off`), waits for network registration (120 s) and prints the
   status. Logged under the tag `wwan-sim`.

`wwan-sim 2 off` undoes step 3: it hangs up LTE (refusing while LTE is up
unless `--force`, as above), selects slot 1 if slot 2 is active, disables
the second interface (`AT!CUSTOM="UIM2ENABLE",0`), resets the modem and
waits for slot 1 as in step 5. The next `wwan-sim 2` enables it again.

`wwan-sim` doesn't bring LTE back up; whoever uses LTE redials (`ifup wwan0`).
The SIM must have no PIN. Both slots share the same APN (see [APN](#apn)):
if the other SIM's carrier doesn't accept it, change it with `wwan-apn`.

`AT!UIMS` and `UIM2ENABLE` are undocumented Sierra engineering commands.

## APN

The APN is not a `wwan-manager` setting: it is stored in the modem, in the PDP
context that `wwan-dial` starts (`QMI_PROFILE`, default 1). The modem keeps
it across resets and power cuts.

```sh
wwan-apn                    # context's APN and PDP type
wwan-apn internet           # set the APN, keep the PDP type
wwan-apn internet IPV4V6    # set APN and PDP type (IP, IPV6 or IPV4V6)
wwan-apn --force internet   # also while LTE is up (hangs it up)
wwan-apn --profile 2 internet.telekom   # another context (default QMI_PROFILE)
wwan-dial up --profile 2    # dial that context instead of QMI_PROFILE
```

It writes the context with `AT+CGDCONT=<QMI_PROFILE>,"<type>","<apn>"`
and reads it back; the new APN takes effect with the next dial. Like
`wwan-sim`, it refuses while LTE is up unless `--force`, and then doesn't
bring LTE back up. Only valid APN names are accepted (labels of letters,
digits and hyphens, separated by dots, at most 100 characters). Logged
under the tag `wwan-apn`. To keep several APNs at hand, put them into
different contexts: write one with `wwan-apn --profile N` and dial it with
`wwan-dial up --profile N`, or make it the default with `QMI_PROFILE`.
`wwan-dial up --profile N` run by hand does not go through `ifup`, so
`ifdown` does not know about it; hang up with `wwan-dial down`.

## SIM PIN

`wwan-manager` needs a SIM without PIN. To switch the PIN lock off for the SIM
in the active slot (`wwan-sim`):

```sh
wwan-pin                # SIM state, PIN lock, tries left
wwan-pin off            # asks for the PIN
echo 1234 | wwan-pin off
wwan-pin change         # asks for the current PIN, then the new one twice
printf '%s\n' 1234 5678 | wwan-pin change    # current, new
```

It uses `AT+CPIN` and `AT+CLCK="SC"`; the tries left come from QMI DMS
"UIM Get PIN Status" (`0x002B`, TLV `0x11`), through
`/usr/lib/wwan-manager/qmi`.
Every wrong PIN costs one of the SIM's tries (usually 3) and the last one
blocks the SIM until the PUK is entered. So `off` only accepts 4–8 digits
and sends nothing when it can't read the tries left or fewer than 2 are
left. A SIM waiting for its PIN is unlocked first, then the lock is
switched off. `change` uses `AT+CPWD="SC"`: it sets a new PIN without
touching the lock (off stays off, on stays on), has the same checks, and
refuses a new PIN equal to the current one. Logged under the tag `wwan-pin`
(never a PIN).

## Diagnostics

`wwan-dial` logs each step to stderr (shown by `ifup`) and to the journal
under the tag `wwan-dial`. If a dial fails, it logs SIM, signal, operator,
registration, low-power votes (`AT!PCINFO?`), `AT!GSTATUS?` (band, RSRP,
EMM/RRC state), PDP contexts and `+CEER`.

```sh
journalctl -t wwan-dial -t wwan-sim -t wwan-pin -t wwan-apn
wwan-at 'AT!GSTATUS?' 'AT!PCINFO?'      # radio state and locks
```

## Configuration

`/etc/default/wwan-manager` (conffile, kept on upgrades). After changing
`LTE_IFACE` or `METRIC`, run `wwan-manager-setup`. Change `TABLE` while LTE is
down: the rules of the old table are only removed at hang-up.

| Option | Default | Meaning |
|---|---|---|
| `LTE_IFACE` | `wwan0` | Modem network interface |
| `METRIC` | `700` | Metric of the LTE default route |
| `TABLE` | `700` | Routing table of the LTE routes; empty = main table |
| `RULE_PREF` | `1000` | Not in the shipped file: priority of the three rules for `TABLE` |
| `FWMARK` | `700` | Not in the shipped file: packets with this mark use `TABLE`; empty = no mark rule |
| `DNS` | `1.1.1.1` | Nameservers over LTE (space-separated); empty = the modem's |
| `AT_PORT` | `/dev/wwan-at` | AT port, used for registration, status, `wwan-sim` and `wwan-pin` |
| `QMI_PROFILE` | `1` | 3GPP profile (PDP context) that `ifup` / `wwan-dial` start and `wwan-apn` shows and writes. Its APN is stored in the modem, see [APN](#apn). `--profile N` on either command overrides it for one call |
| `LOW_POWER` | `no` | `yes` = hang-up also switches the radio off, as `wwan-dial off` |

## Build and install

```sh
make                    # → dist/wwan-manager_1.0.1_all.deb
make VERSION=1.0.2      # another version
make clean
dpkg -i dist/wwan-manager_*.deb
```

Depends on: ifupdown, iproute2, util-linux, coreutils, python3, systemd,
udev.

- **Install / upgrade:** generates the stanza and the interface-name rule,
  renames an already present modem interface and creates `/dev/wwan-at`
  for a plugged-in modem.
- **Removal:** hangs up LTE and deletes the generated files.

## Operating it

```sh
ifup wwan0                                # dial
ifdown wwan0                              # hang up
wwan-dial down                            # hang up, also while wwan0 is down
ifdown wwan0; wwan-dial off               # hang up and switch the radio off (LOW_POWER=yes: ifdown alone)
wwan-dial on                              # radio on again, without dialing
journalctl -t wwan-dial
```
